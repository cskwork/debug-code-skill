Agent skill에이전트 스킬

Find the earliest violated invariant, not the line that crashed. 터진 줄이 아니라 처음 깨진 불변식을 찾아라.

A skill that teaches your coding agent to diagnose hard production and legacy-code bugs when access is partial. Evidence-first, access-aware, and it never hides a symptom.

접근 권한이 제한적인 상황에서 프로덕션·레거시 버그를 진단하도록 코딩 에이전트를 가르치는 스킬. 증거 우선, 접근 권한 인식, 증상을 덮지 않는다.

Symptom 
// duplicate invoices
// after queue retry
func process(msg Message) {
  inv := repo.Find(msg.ID)
  if inv == nil {
    inv = newInvoice(msg)
  }
  // ... writes + sends
  repo.Save(inv)
}

// surface: 500 error
// at the Save() call
Earliest violation 
// the bug is here:
// check-then-act race
inv := repo.Find(msg.ID)
if inv == nil {
  inv = newInvoice(msg)
}

// two retries pass the
// nil check before either
// commits. both write.

// fix: idempotency key +
// unique constraint, not
// a bigger timeout.

The signal hierarchy신호 우선순위

Build the strongest available signal가장 강력한 신호부터 만든다

Production access is rarely complete. The skill never blocks on the ideal — it works in code-only mode and tightens proof as evidence arrives.

프로덕션 접근 권한이 완전한 경우는 드물다. 이상적인 조건을 기다리지 않고 코드만으로 시작하며, 증거가 들어올수록 증명을 강화한다.

L1

Red loop재현 루프

A failing test reproduces the exact symptom at the real seam.

실패하는 테스트가 실제 지점에서 정확한 증상을 재현한다.

L2

Production evidence프로덕션 증거

A repeatable log, trace, or bounded read-only query shows the violated invariant.

반복 가능한 로그·트레이스·제한된 읽기 전용 쿼리가 깨진 불변식을 보여준다.

L3

Surrogate대체 재현

A local/dev fixture preserves the production condition and fails the same way.

로컬/개발 픽스처가 프로덕션 조건을 보존하고 같은 방식으로 실패한다.

L4

Static-only정적 분석만

Code, history, and contracts support a hypothesis. Lowers confidence, does not block.

코드·이력·계약이 가설을 뒷받침한다. 신뢰도는 낮지만 진단을 막지는 않는다.

Trace the bug chain버그 체인을 추적하라

The first boundary where behavior diverges from the invariant is more informative than the final exception.

동작이 불변식에서 처음 벗어나는 지점이, 최종 예외보다 훨씬 더 많은 것을 알려준다.

1
Trigger + first invalid state트리거 + 최초 무효 상태 Duplicate delivery, no idempotency 중복 전달, 멱등성 없음 Two retry messages pass the nil check before either commits. 두 재시도 메시지가 커밋 전 nil 검사를 동시에 통과한다.
↓
2
Propagation전파 Both write a duplicate invoice 둘 다 중복 인보이스를 기록 No unique constraint, so both inserts succeed. 유일 제약이 없어 두 insert 모두 성공한다.
↓
3
Visible symptom표면 증상 500 on the second Save() 두 번째 Save()에서 500 The crash is at the surface, not the cause. 충돌은 표면에서 발생하고, 원인이 아니다.
Separate 구분하라: Fact사실, Inference추론, Unknown미지..

Never present code-only reasoning as an observed production fact. State what remains unverified.코드만의 추론을 프로덕션 관측 사실로 말하지 마라. 검증되지 않은 것을 명시하라.

What the skill enforces스킬이 강제하는 것

  • 01
    Incident gate first사고 게이트 우선If the symptom suggests active harm, it recommends containment and evidence preservation before deep diagnosis.증상이 활성 피해를 시사하면 심층 진단 전 격리와 증거 보존을 권장한다.
  • 02
    3–5 falsifiable hypotheses3–5 반증 가능 가설Each with a prediction and a cheapest probe, before editing any code.각각 예측과 최소 비용 탐침을 가지고, 코드 수정 전에 생성한다.
  • 03
    Regression test before fix수정 전 회귀 테스트Locks the bug down at the closest truthful seam, then applies the smallest safe patch.가장 가까운 진짜 지점에서 버그를 잡고, 가장 작은 안전한 패치를 적용한다.
  • 04
    Adversarial verification대항 검증Reruns the strongest signal, then challenges: does this fix the cause or the manifestation?가장 강한 신호를 재실행하고 도전한다: 원인을 고치는가, 표면을 가리는가?

What it refuses to do거부하는 것

✕Catch-all that swallows the exception예외를 삼키는 catch-all
✕Silent default masking bad state잘못된 상태를 숨기는 기본값
✕Broad retry without idempotency멱등성 없는 광범위 재시도
✕Larger timeout as the only change유일한 변경이 타임아웃 증가
✕Disabling validation or constraints검증이나 제약 비활성화
✕Rewriting legacy before the cause is proven원인 증명 전 레거시 재작성

The workflow워크플로우

From symptom to smallest safe fix증상에서 최소 안전 수정까지

01

Incident gate사고 게이트

Contain active harm. Preserve evidence. Decide if investigation is safe.

활성 피해를 격리한다. 증거를 보존한다. 조사가 안전한지 결정한다.

02

Establish access접근 권한 파악

One compact question for missing high-leverage info. Code-only is valid.

빠진 핵심 정보를 한 번만 묻는다. 코드만으로도 유효하다.

03

Orient & trace탐색 & 추적

Read deeply. Build the bug chain. Cite concrete code at every link.

깊이 읽는다. 버그 체인을 만든다. 모든 연결에 코드를 인용한다.

04

Rank hypotheses가설 정렬

3–5 falsifiable hypotheses. Probe the cheapest discriminator.

3–5 반증 가능 가설. 가장 저렴한 구분 탐침을 시도한다.

05

Probe surgically정밀 탐침

Every probe maps to a prediction. Bounded, read-only, operator-run.

모든 탐침은 예측에 대응한다. 제한적, 읽기 전용, 운영자 실행.

06

Fix at the root근본 수정

Regression test first. Smallest patch to the earliest violated invariant.

회귀 테스트 우선. 최초 깨진 불변식에 가장 작은 패치.

07

Verify adversarially대항 검증

Rerun the strongest signal. Challenge the result. Separate local vs prod proof.

가장 강한 신호 재실행. 결과에 도전. 로컬과 프로덕션 증명을 분리.

08

Report honestly정직한 보고

CONFIRMED | PROBABLE | POSSIBLE | INCONCLUSIVE. State what is unverified.

CONFIRMED | PROBABLE | POSSIBLE | INCONCLUSIVE. 검증되지 않은 것을 명시.
